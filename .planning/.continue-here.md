# BLOCKING CONSTRAINTS — Read Before Anything Else

- [ ] CONSTRAINT: Never set `idleTimeoutMillis: 0` on the Prisma `pg` pool adapter — `pg-pool`'s eviction-timer setup is gated on a truthy check (`if (this.options.idleTimeoutMillis && ...)`), so `0` disables idle-connection cleanup entirely instead of enabling it. This is backwards from what it sounds like it does. Verified against `node_modules/pg-pool/index.js` directly, don't take an external review's word for pg semantics without checking the source.

**Do not proceed until the box above is checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Piping `npm run type-check` / `npm run lint` through `\| tail -N` | Masks a non-zero exit code from the *first* command in the pipe — `tail`'s own exit code (0) wins. A genuine `tsc` crash read as "clean" every time it was checked this way, hiding a broken CI deploy for hours. | blocking | Always run with output redirected to a file and check `$?` directly: `cmd > out.txt 2>&1; echo "EXIT=$?"; tail -N out.txt`. Never trust a piped-through-tail "no errors visible" as proof of a clean run. |
| Trusting local `npm run build` success as proof CI will pass | The GitHub Actions build step passes the **production** `DATABASE_URL` for build-time ISR prerendering — a different, much slower connection than local dev DB. A local build can pass while CI fails for reasons specific to that connection, or vice versa (as happened: local passed because a tsc crash was masked, see above). | advisory | When diagnosing a CI-only failure, get the actual CI log (paste from user, or an authenticated API path) rather than assuming local reproduction covers it. |
